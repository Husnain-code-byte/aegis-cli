## Press Release

**Aegis CLI — Commands That Just Work, Every Time**

Aegis now has a command parser that gets out of your way. Type `aegis start`, `aegis phase`, or `aegis status` and the CLI routes your command to the right handler instantly. No ceremony, no configuration, no guesswork.

Every command is a single word: `start`, `phase`, `prompt`, `agent`, `status`, `config`, `workflow`. Each one has a short help description, and `--help` on any command shows you exactly what it does. Type `aegis --help` to see all 8 commands at a glance. Type `aegis agent --help` to see agent options. Type `aegis` with no arguments and you get help automatically.

Type something wrong and Aegis tells you kindly: `[ERROR] Unknown command 'starrt'. Did you mean 'start'?` — with Levenshtein-based suggestions. Global flags like `--json` and `--no-color` work before or after any command: `aegis --json status` produces the same result as `aegis status --json`.

The parser is the foundation of everything Aegis does. It handles argv parsing, command registration, handler dispatch, flag detection, and error reporting in under 50 milliseconds. Every subsequent feature — workspace scanning, phase detection, prompt generation — routes through this parser, which is exactly as fast, predictable, and helpful as it should be.

## FAQ

### Q: What commands does Aegis support?

A: Aegis registers 8 commands out of the box. Each maps to a dedicated handler module:

| Command | Handler File | Description |
|---------|-------------|-------------|
| `start` | `commands/start.ts` | Full dashboard with phase, status, and prompt |
| `phase` | `commands/phase.ts` | Show current ANSDLC phase info |
| `prompt` | `commands/prompt.ts` | Generate a prompt for Claude Code |
| `agent` | `commands/agent.ts` | Agent details or directory listing |
| `status` | `commands/status.ts` | Workspace summary |
| `config` | `commands/config.ts` | API key and configuration management |
| `workflow` | `commands/workflow.ts` | Workflow operations (future/placeholder) |
| — (implicit) | — | Help (no command = `--help`) |

### Q: What happens when I type an unknown command?

A: Aegis responds with a friendly error on stderr: `[ERROR] Unknown command '<input>'. Did you mean '<suggestion>'?` with up to 3 Levenshtein-based suggestions. The process exits with code 1. No stack traces, no confusing output.

### Q: How do global flags work?

A: Two global flags are supported: `--json` and `--no-color`. Both can appear before or after the command name:

- `aegis --json status` — JSON output for `status`
- `aegis status --json` — same result
- `aegis --no-color start` — dashboard without terminal colors
- `aegis --no-color --json phase` — both flags combined

In addition, `--version` (or `-V`) prints the version string and exits. `--help` (or `-h`) prints help text for any command.

### Q: What does `aegis help` do?

A: `aegis help` is treated as an explicit command that shows global help, equivalent to `aegis --help`. This matches the CLI convention used by git, npm, and other popular tools. All 8 commands are listed with their descriptions.

### Q: How does the `agent` command handle arguments?

A: The `agent` command accepts an optional `[name]` argument:
- `aegis agent decomposition-guide` — routes to the agent handler with `"decomposition-guide"` as the agent name
- `aegis agent 00` — routes to the agent handler with `"00"` as the agent number (numeric agent IDs are valid per subsystem map)
- `aegis agent` — routes to the agent handler with no name, which triggers directory listing mode
- `aegis agent --help` — shows agent-specific help with usage

The handler (not the parser) decides what to do with the name — whether to look up the agent, display its card, or list all agents.

### Q: How does the `config` command handle subcommands?

A: The `config` command defines subcommands using Commander's nested command API:
- `aegis config key` — routes to the config handler with `"key"` as the subcommand
- `aegis config` (no subcommand) — displays config subcommand help via Commander's built-in help cascade

Subcommand help is generated by Commander's help system, not by Aegis directly.

### Q: Are command names case-sensitive?

A: Yes. Commander v15 uses case-sensitive matching. `aegis START` is treated as an unknown command, not equivalent to `aegis start`. This is intentional: Commander does not perform case normalization, and adding it would introduce ambiguity with future commands.

## Success Criteria

1. **All 8 commands route correctly** — executing `aegis <command>` invokes the correct registered handler for every command in the registry
2. **Agent argument optional** — `aegis agent` routes without a name argument; `aegis agent <name>` routes with the name
3. **Config subcommand** — `aegis config key` routes with subcommand; `aegis config` shows config help
4. **Version output** — `aegis --version` prints `aegis-cli v0.1.0` and exits with code 0
5. **Help output** — `aegis --help` lists all 8 commands; `aegis <command> --help` shows command-specific help
6. **No-args help** — `aegis` with no arguments is equivalent to `aegis --help`
7. **Global flags parsed** — `--json` and `--no-color` are detected as boolean flags and passed to handlers
8. **Flag position independence** — flags work before and after the command name, including mixed positioning (`aegis --no-color start --json`)
9. **Unknown command handled** — unknown command prints `[ERROR] Unknown command '<input>'. Did you mean '<suggestion>'?` with Levenshtein suggestion on stderr, exit code 1
10. **Consistent error format** — all parsing errors use `[ERROR]` prefix on stderr, exit code 1. Note: non-parsing errors in future features may use different exit codes (2, 3) per the subsystem map.
11. **Short flags supported** — `-V` for version, `-h` for help
12. **`aegis help` command** — explicit `help` command shows global help, equivalent to `--help`
13. **Parse latency** — argv parsing completes in under 50ms for all commands
14. **Extra whitespace tolerance** — multiple spaces between arguments are handled correctly (shell normalizes, but intra-arg parsing is robust)
15. **TypeScript strict** — all parser code compiles with TypeScript strict mode, no `any` types

## Anti-Goals

1. **NOT implementing command handlers** — F-002 routes to handler stubs; handler behavior (dashboard display, prompt generation, agent lookup) is implemented in later features
2. **NOT workspace scanning** — F-002 does not read files, detect `.claude/` directories, or validate workspace state
3. **NOT JSON output rendering** — `--json` is parsed and passed to handlers; actual JSON serialization is the handler's responsibility
4. **NOT `--no-color` enforcement** — the flag is parsed and passed; color suppression logic is the Terminal UI subsystem's responsibility
5. **NOT Levenshtein algorithm implementation** — suggestion logic is imported from `fast-levenshtein` or Commander's built-in suggestion; F-002 only integrates it
6. **NOT persistent state** — no configuration files, no cache, no session state
7. **NOT case-insensitive matching** — uppercase commands are treated as unknown; case normalization is not implemented
8. **NOT `aegis init`** — no project initialization command; workspace setup is out of scope
