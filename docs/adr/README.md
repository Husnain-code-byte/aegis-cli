## Status Definitions

| Status | Meaning |
|--------|---------|
| **Proposed** | Decision proposed for review, not yet accepted |
| **Accepted** | Decision accepted, will be implemented |
| **Deprecated** | Decision no longer recommended, but still in use |
| **Superseded** | Replaced by a newer ADR (referenced in the body) |

## File Naming Convention

`NNNN-lowercase-kebab-case.md` where `NNNN` is the zero-padded ADR number.

## Process

1. A new ADR is proposed as part of the architecture design phase (Phase 3)
2. Each ADR must explicitly state the decision, the context, alternatives considered, and consequences (what we gain and what we give up)
3. ADRs are stored in Git alongside the code — the commit history provides the timeline
4. When an ADR is superseded, it links to the superseding ADR
